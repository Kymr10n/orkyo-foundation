## 1. Executive summary

The codebase is in better shape than its size suggests. Conventions are written down, most of
them have a mechanical guard, type hygiene on the frontend is near-perfect (zero `any`, zero
`@ts-ignore` in production code), CI pins every action by SHA, and previous declutter passes
have already removed the easy dead weight. The debt that remains sits where the guards cannot
reach, and it clusters into five themes.

**Identity and session edges are the weakest area.** Four findings are critical: the calendar
subscription group is the only tenant route group without a membership check; dormant users
are deactivated and purged even when the warning email never sent; the purge relies on a
`users.keycloak_id` column that nothing in foundation writes, so the Keycloak disable/delete
silently no-ops; and a failed BFF token refresh keeps a session alive for up to 14 days, with
`logout-all` never touching the BFF session store. Several significant findings sit next to
these: email linking ignores `email_verified`, client IP is spoofable, site-admin user actions
are not audited, and the role cache is never evicted on demotion.

**The same rule is written twice and the copies have drifted.** Criterion applicability is
answered three different ways in SQL; Insights, Utilization and Reporting compute "blocked
minutes", "completed" and "conflict" differently and show different numbers for the same data;
two admin settings surfaces write the same table with different keys and caches, one of them
storing values nothing reads; audit writers, membership queries, template export, capability
repositories and eight frontend dialogs are copy-pasted.

**Reads are unbounded or silently truncated.** Six repositories hard-code `LIMIT 200/500` on
"get all" reads that feed export and presets. The paged request list ignores `siteId`. Nothing
on the frontend reads `hasNextPage`. Several Viewer-callable endpoints accept an unbounded date
window. Global search cannot use the GIN indexes its migration created.

**The test suite has tests that cannot fail.** One 13-test file accepts 400, 201 or 500. The
test host maps an unknown role to Admin and re-implements the production enrichment middleware.
A fixture helper returns a GUID nothing creates and 49 call sites depend on test order. On the
frontend, the largest page test mocks 35 modules including pure domain functions and stores.

**CI and docs carry churn.** A baseline-advance bot authors 15 of the last 50 commits on `main`,
mostly with no migration change. The published Keycloak tag says 26.6 while the image is 26.7.3.
The pre-commit hook stages files the developer left unstaged. Eleven of eighteen files in
`docs/` are historical plans or reviews, one of which holds an untracked open security item.

The good news is that most fixes are deletions: dead migrator modes, a redundant workflow,
tests that assert nothing, service-side shape guards that validators already enforce, a
`RuntimeConfig` surface nothing reads, and a fire-and-forget session rewrite whose field has no
reader.

## 4. Do not touch

Code that looks odd but is intentional, documented, already tracked, or not worth the churn.

- **No `tenant_id` filter in org repositories.** Each tenant has its own database; `RepositoryScopingTests` enforces the connection scoping. Only control-plane stores filter (S47 asks for tests, not code).
- **The Community seams:** `AllowAll*`, `NoOp*`, `Null*`, `PassThrough*`, `SinglePlanInfoProvider`, `SingleTenantDbConnectionFactory`, `IAdminAuditService` with one implementation, and the SaaS-only registrations in `AddFoundationServices` that `check-dead-registrations.py` flags offline (saas injects them).
- **`AvailabilityResolver`'s two `GetBlockedPeriodsForResourcesAsync` overloads** — the doc explains that merging them changes which resources see site closures.
- **Invitation tokens hash to base64, calendar feeds to hex** — converging is a migration, documented in `SecureTokens.cs`.
- **`AnthropicGateway` builds a client per call** — per-workspace-key isolation, documented.
- **API-access and reporting tokens as separate classes and tables** — a trust-class boundary.
- **`WorkerJobCoordinator` reimplements FNV-1a** so Core does not depend on the migrator.
- **`FoundationMigrationModule.TenantDatabaseOnlyIds` hard-codes two ids** — applied SQL is immutable.
